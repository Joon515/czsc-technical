# czsc-technical · 缠论指标

一个 TradingView **Pine v6** 技术指标：缠论的同图结构——笔、线段、中枢画到图表上，再把均线、MACD、量能当辅助证据挂在确认K线旁边,就一个 `.pine` 文件，没有第三方库，只读本图行情，不请求跨周期数据。

## 它是什么

- 一个指标，一个文件：`pine/chanlun.pine`（Pine v6，1300 行左右），无第三方库。
- 只用当前图表的行情，不跨周期取数。
- 图上只保留价格结构、原买卖点和确认K旁的短提示：不画 MA 线、MACD 线/柱、量柱、均量线，不建成交量轴，也没有辅助数值面板。声明为 `overlay=true, scale=scale.none`。
- MA/MACD/VOL 仍然在内部计算，结论转进确认K标记的悬浮说明，不改动K线本身的涨跌颜色。
- 原结构买卖点标在发生的极点，文字保持单行；辅助符号标在事件**收盘确认**的那根K上，不回标成"发生时就已经知道"。

**它不是**：交易系统、预测工具、多周期级别研究、完整走势类型的证明。买卖点标记是结构记号，不是指令。

## 快速开始

1. TradingView 任意图表 → Pine Editor → 新建指标。
2. 粘贴 `pine/chanlun.pine` 全文，保存，添加到图表。
3. 图上出现蓝色 S1 线段、中枢方框和买卖点标记，就算装好了。

从旧版本升级：

- 先移除旧指标实例再添加新实例；如果旧坐标轴范围还残留，重加后再恢复价格轴自动缩放。
- 已有服务器提醒是快照，改完源码必须重建。
- 脚本不碰你的手工绘图；如果对象树里确认那是个独立的 Text 图形，单独隐藏它就行。

## 图上有什么

### 结构层 S1 / S2 / S3

默认开启叠层，共 3 层：

| 层 | 来源 | 颜色 |
| --- | --- | --- |
| S1 | 确认笔组成的线段 | 蓝 |
| S2 | 把确认 S1 段的连接节点继续分段 | 橙 |
| S3 | 把确认 S2 段的连接节点继续分段 | 紫 |

- 各层独立确认，只向上传递冻结段；段数不够就不画，也不复制下层的输出。关闭叠层后只计算并绘制 S1。
- 分段用首尾相连的冻结节点；中枢取其时间区间内原K的完整高低范围，不把内部极值接成反时序的笔。
- 笔固定第 77 课口径。

**别把 S1/S2/S3 当级别**：它们是同图结构层，不是 1／5／30 分钟级别，也不构成原著"全部走势类型递归"的证明。

### 显示与样式

默认显示线段、中枢核心和标记；笔、未完成虚线、大状态面板默认关闭，去"显示"组打开。

"显示"组里只有开关；颜色和字号在"样式"组，因为 Pine 的 Style 页只收 plot 类对象，标签/线/框的样式进不去。可以调：买向、卖向、冲突提示、S1/S2/S3、笔的颜色，K线提示/状态字号（默认小）和结构点字号（默认正常）。线宽按层级固定 S1/S2/S3 = 1/2/3；中性灰跟随图表前景色自适应，不做成输入。

### 中枢方框

- 核心固定为首三段实际区间的闭交 **[ZD, ZG]**，允许单价交集；GG/DD 是同向 Z 段包络。
- 横向只覆盖第一成员起点到最后一个被接纳成员的终点，不会因为确认时刻把框拉长——这是显示约定，不冒称原文坐标。
- 完整离开先暂时冻结；回试返回才接纳"离开 + 返回"两段并延伸。三类破坏后永久冻结，连接段不进新中枢。
- 三买回试低点 `≥ ZG`、三卖回试高点 `≤ ZD`，触及边界也算破坏（第 20 课）。

### 买卖点标记

买向是绿色小上箭头，卖向是红色小下箭头，文字形如 `3买·S2`（`S2` 是结构层）。候选 `1?` / `2?` 半透明显示。

- `1?`/`2?` 永远是候选：没有严格背驰力度证据。
- `3` 是本层的区间破坏标记。
- 确认滞后于发生。回标不代表当时可知，更不代表能按那个价格成交。

### 提醒

提醒包含确认买卖、收盘进出中枢、分层合取三块；候选默认不提醒。

- 合取要求同类别、同方向、同候选身份，默认至少 2 层、确认间隔 ≤ 20 根本图K线。同源行情不算独立周期证据。
- Create Alert 时选独立条件或 **Any alert() function call**。
- JSON 里带匹配的 `levels`、本图 `timeframe`、类别、方向、发生/确认/观察时间与价格；每次收盘最多一条聚合消息。
- 旧提醒是服务器快照，改源码后必须重建。

**盘中进出中枢**（默认开）是三条独立条件：盘中离开上沿、离开下沿、回到中枢内。比较对象是现价与前一确认收盘、以及最新确认中枢。中枢仍然来自确认结构，所以盘中出现的离开/回归可能在收盘前撤回。建提醒时频率选"每根K线一次"，避免同一根K重复。

盘中条件不进 `alert()` 的 JSON，也不含买卖点：买卖点需要未确认K上的结构回滚，当前未实现，仍然只在确认后提醒。

### 预算

"高级"组里：已确认原K预算默认 18000，每类结构对象预算默认 6000。耗尽会明确停止、显示原因并保留确认状态；淘汰旧图形不影响计算历史——左边不知道的结构，它就是不知道。

## 辅助指标

先讲原则：结构摄入不依赖辅助指标的暖机、量能或显示开关；辅助状态只接实际摄入的收盘原K，预算拒收的那根不会推进辅助状态。辅助证据不新增独立买卖提醒，也不会把候选升级成严格买卖点。

### MA 吻

默认 SMA 5/10。吻开始：穿越、反向，或快线顺向斜率变缓（含停平）；吻结束：先缩距/穿越/斜率恢复，再重新顺向分离——没缩距的飞吻不会直接结束。实际换边是湿吻；碰线后沿原侧恢复不算湿吻。没穿越时，用"最小间距 / 吻前峰值 ≤ 0.5"近似区分唇吻和飞吻。

原文没有这些数字阈值——这是我拍的近似（可配置），不是吻的充分必要条件。

### S 层 MACD

默认 12/26/9（Pine `ta.macd`，柱 = DIF − DEA）。只跟本层上一个同向冻结段比：统计原K `(at,bt]` 的方向柱面积 `sum(max(dir*hist,0))` 和方向 DIF/DEA 峰值，正负柱不相抵。间隔中两线同时落进各自前段峰值的 20% 以内记"回零参考"（比例可配）。

它不能把反向段冒称中枢 B，也没有自动证明第 24 课的 A/B/C 角色。MACD 在一字板这类行情下的局限仍然在。

### VOL

段间比较**平均每根**成交量，不用总量——总量会把长段误报成强。同样取 `(at,bt]`，共享端点只归前段。逐根量比只对比前 20 根均量、排除本根；默认 ≥2 倍算放量、≤0.5 倍算缩量。

"前一根放量、这一根骤缩"会提示缠绕风险参考，这是对第 12 课定性描述的近似，不是卖点，也不是骗线结论。

### 未知不当弱势

缺任意一根量，这个窗口/段的均量就是未知；真实零量保留，零基准不产生比率。MACD 各项缺值独立传播。没有前同向段就等着，不跨层比较，也不把延伸中的虚线存成基准。

### 确认K辅助标记

"K线辅助"里的"确认K辅助标记"默认开。买向标记在确认K下方，卖向在上方；同一根K、同一方向的多层事件合并成一个标记，双向分别保留，同一根K最多两个。符号只有四种：

| 符号 | 含义 |
| --- | --- |
| ● | 本K该方向事件都拿到了三辅减弱参考 |
| ○ | 有中性/分歧，但没有缺项、也没有增强反证 |
| ? | 有缺项，但没有已知的增强反证 |
| ! | 至少一个事件存在增强反证（琥珀色） |

冲突优先于缺项，中性和支持其次；颜色不代表买卖指令。悬停会逐条列出同向事件的 MA/MACD/量能状态（相对前同向段），外加本K的 MACD 柱与量比。

最多保留最近 180 个标记，走独立队列，不挤占原 240 个结构点标签；关掉标记不影响计算、结构或提醒。

### 同层证据怎么算

- **MA**：段内 `max(dir*(短MA−长MA),0)` 的平均间距减弱/增强——是段内平均，不是瞬时值，也不是吻的判定；段终点的吻状态来自当时的原K快照。
- **MACD**：柱面积减弱、且 DIF/DEA 方向峰值都没增强，才算减弱参考；任意一项增强标冲突；缺项不伪支持。
- **VOL**：均量收缩/扩张。真实 0 参与比较，0 对 0 为中性；缺值未知。

### 三辅支持

"候选仅显示/提醒三辅支持"默认关闭。打开后只筛 `1?`/`2?` 的显示与提醒：不删结构记录、不影响上层输入、也不筛三类事件。它是可选的保守筛选，不是原文的硬三合公式，也不证明严格背驰。

### 悬浮与 JSON

原结构点的悬浮说明包含结构原因、发生/确认/观察时间与价格、本段的辅助状态，以及相对前同向段的比值（`<1` 减弱，`>1` 增强）。确认K标记的悬浮列出同一根K上各事件的辅助状态。

证据的比较都发生在同一层的相邻同向冻结段之间：不跨层，也不把别的区间混进来。

买卖事件 JSON 的冻结 `auxiliary` 保留 `scope/current/previous/intervening_zero_reference`，新增 `evidence`（`ma/macd/volume`：0 缺项、1 减弱、−1 增强、2 中性；`supported`）；区间新增 `ma_mean_gap/ma_kiss_at_end`，原有的时间界、方向、根数、MACD 面积/峰值、均量保留。未知数值为 JSON `null`；中枢进出事件仍然 `auxiliary=null`；合取快照属于代表事件的层，不是各层力度的合成。

## 开发与验证

```sh
npm ci              # 安装 PineTS 0.11.0（唯一的 devDependency）
npm test            # Node + PineTS 跑 42 个用例
npm run check:pine  # 调 TradingView 网页的非公开编译端点，做一次源码诊断
```

几个必须说清的局限：

- PineTS 是独立运行器；编译接口未公开、可能变更。**编译不等于图表执行**，两者都不替代 TradingView 上的实时回滚、Bar Replay、服务器通知实测。
- 辅助计算/格式化函数保留"局部结果赋值后返回"的普通 Pine 写法，绕开 PineTS 0.11.0 连续转译含调用的条件返回式时污染共享 AST 的问题；不改运行器依赖，也不改验证断言。
- PineTS 把 `force_overlay` 绘图放进独立 overlay 容器，验证读取器两块真实快照都读；原几何断言保持原样。图表验证用原装 adapter 和价格坐标，不搞双轴桥接，也不伪造曲线。
- 离线 BTC 夹具是真实 OHLC + 5 分钟间隔，只平移到了固定历史时钟，**不含成交量**——所以它不能用来验证 VOL。合成 OHLCV、或给真实 OHLC 配的合成量，都不冒充交易所的价和量。

## 边界清单（诚实版）

- 不预测；确认永远滞后于发生，标记不代表当时可操作。
- 不画均线、MACD、量能，只把结论挂到标记上。
- 只用本图数据，不做多周期级别递归。
- `1?`/`2?` 永远是候选；本实现没有证明严格背驰。
- S1/S2/S3 是同图结构层，不是级别。
- 提醒只是提醒，没有自动交易。
- 原文没给数字的地方（唇吻、回零、放量阈值），这里的数字都是可配置近似。
